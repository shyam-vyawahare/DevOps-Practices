# Docker Volumes

## 🎯 Objective

Understand Docker volumes and learn how to persist data generated by containers.

---

## 1. What is a Docker Volume?

A Docker container is temporary by nature. When a container is removed, the data stored inside its writable layer is normally lost.

**Docker Volumes** provide persistent storage that exists independently of a container.

```text
Container
    │
    │ writes data
    ▼
Docker Volume
    │
    ▼
Persistent Data
```

Even if the container is deleted, the volume can remain and be reused by another container.

---

## 2. Why are Volumes Important?

Volumes are useful when an application needs to preserve data.

Common examples:

- Databases
- Uploaded files
- Application data
- Logs
- Configuration data
- Development environments

For example:

```text
PostgreSQL Container
        │
        ▼
PostgreSQL Volume
        │
        ▼
Database Data
```

If the PostgreSQL container is deleted, the database data can still remain in the volume.

---

## 3. Create a Docker Volume

Create a volume:

```bash
docker volume create devops-data
```

List volumes:

```bash
docker volume ls
```

Example:

```text
DRIVER    VOLUME NAME
local     devops-data
```

---

## 4. Inspect a Volume

Use:

```bash
docker volume inspect devops-data
```

This displays information such as:

- Volume name
- Driver
- Mount point
- Scope

---

## 5. Mount a Volume to a Container

Run an Nginx container with the volume:

```bash
docker run -d \
  --name volume-demo \
  -v devops-data:/usr/share/nginx/html \
  nginx
```

Here:

```text
-v devops-data:/usr/share/nginx/html
```

means:

```text
Docker Volume
devops-data
     │
     ▼
/usr/share/nginx/html
     │
     ▼
Nginx Container
```

---

## 6. Store Data in the Volume

Create a file inside the container:

```bash
docker exec volume-demo sh -c \
'echo "Hello from Docker Volume" > /usr/share/nginx/html/index.html'
```

Check the file:

```bash
docker exec volume-demo cat /usr/share/nginx/html/index.html
```

Expected output:

```text
Hello from Docker Volume
```

---

## 7. Delete the Container

Remove the container:

```bash
docker rm -f volume-demo
```

The container is gone, but the volume still exists.

Check:

```bash
docker volume ls
```

You should still see:

```text
devops-data
```

---

## 8. Reuse the Volume

Create another Nginx container using the same volume:

```bash
docker run -d \
  --name volume-demo-2 \
  -v devops-data:/usr/share/nginx/html \
  nginx
```

Read the previous data:

```bash
docker exec volume-demo-2 \
cat /usr/share/nginx/html/index.html
```

Expected output:

```text
Hello from Docker Volume
```

This demonstrates **data persistence**.

---

## 9. Named Volumes vs Bind Mounts

Docker commonly uses two approaches for mounting data.

### Named Volume

```bash
docker run -v devops-data:/app/data nginx
```

Docker manages the storage location.

```text
Container
    │
    ▼
Named Volume
    │
    ▼
Docker-managed storage
```

### Bind Mount

```bash
docker run -v $(pwd)/data:/app/data nginx
```

A specific directory on the host is mounted into the container.

```text
Host Directory
      │
      ▼
Container Directory
```

### Difference

| Feature | Named Volume | Bind Mount |
|---|---|---|
| Managed by Docker | Yes | No |
| Host path required | No | Yes |
| Good for databases | Yes | Possible |
| Good for development | Good | Excellent |
| Portability | Higher | Lower |

## 10. Docker Compose Volumes

Volumes are commonly used with Docker Compose.

Example:

```yaml
services:

  database:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: example
    volumes:
      - postgres-data:/var/lib/postgresql/data

volumes:
  postgres-data:
```

The important section is:

```yaml
volumes:
  - postgres-data:/var/lib/postgresql/data
```

This stores PostgreSQL data in a persistent Docker volume.

---

## 11. Volume Lifecycle

The relationship can be visualized as:

```text
Create Volume
      │
      ▼
Start Container
      │
      ▼
Write Data
      │
      ▼
Stop/Delete Container
      │
      ▼
Volume Still Exists
      │
      ▼
Create New Container
      │
      ▼
Mount Same Volume
      │
      ▼
Data Available Again
```

---

## 12. Useful Docker Volume Commands

### List volumes

```bash
docker volume ls
```

### Create volume

```bash
docker volume create volume-name
```

### Inspect volume

```bash
docker volume inspect volume-name
```

### Remove volume

```bash
docker volume rm volume-name
```

### Remove unused volumes

```bash
docker volume prune
```

> ⚠️ `docker volume prune` can permanently delete unused volumes. Use it carefully.

# 🧪 Hands-On Practice

## Task 1 — Create a Volume

```bash
docker volume create practice-volume
```

Verify:

```bash
docker volume ls
```

---

## Task 2 — Create a Container

```bash
docker run -d \
  --name practice-container \
  -v practice-volume:/data \
  alpine \
  sh -c "while true; do sleep 3600; done"
```

---

## Task 3 — Write Data

```bash
docker exec practice-container \
sh -c 'echo "DevOps Persistence Practice" > /data/message.txt'
```

Read it:

```bash
docker exec practice-container cat /data/message.txt
```

---

## Task 4 — Delete the Container

```bash
docker rm -f practice-container
```

---

## Task 5 — Create a New Container

```bash
docker run -d \
  --name practice-container-2 \
  -v practice-volume:/data \
  alpine \
  sh -c "while true; do sleep 3600; done"
```

Read the old data:

```bash
docker exec practice-container-2 cat /data/message.txt
```

Expected output:

```text
DevOps Persistence Practice
```

This proves that the data survived the deletion of the first container.

---

## Task 6 — Clean Up

Remove the container:

```bash
docker rm -f practice-container-2
```

Remove the volume:

```bash
docker volume rm practice-volume
```

---

# 🔑 Key Takeaways

- Containers are generally ephemeral.
- Docker volumes provide persistent storage.
- A volume can survive container deletion.
- The same volume can be mounted by multiple containers.
- Named volumes are managed by Docker.
- Bind mounts connect a specific host directory to a container.
- Volumes are especially important for databases and stateful applications.
- Docker Compose can automatically create and manage volumes.
